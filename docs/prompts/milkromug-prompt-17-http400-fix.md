# Задача: Починить HTTP 400 при захвате чатов DeepSeek, Google AI и длинных чатов.

## Контекст
При клике на букмарклет на страницах DeepSeek, Google AI и больших чатах сервер возвращает HTTP 400. Букмарклет отправляет данные, но Spring Boot их отклоняет.

## Шаги
1. **Серверное логирование:** В `ChatController.java` добавить `try-catch` на десериализацию Jackson. Если JSON битый, логировать в консоль первые 200 символов сырого payload и возвращать `400 Bad Request` с понятным текстом ошибки, а не стектрейсом.
2. **Увеличение лимитов:** В `application.properties` добавить `server.tomcat.max-http-form-post-size=10MB` и `spring.jackson.parser.max-string-length=10000000`.
3. **Универсальный DOM-парсер (Эвристика):** В `bookmarklet.js` переписать сборщик сообщений. Если точечные селекторы не сработали, использовать эвристику: искать повторяющиеся блоки текста, чередующиеся с блоками "user/assistant" или "я/ИИ".
4. **Санитизация на клиенте:** Перед отправкой `fetch` на `/chat`, прогнать собранный текст через функцию, которая жестко экранирует все `\n`, `\r`, `"`, `\` в безопасные Unicode-последовательности, чтобы JSON точно не порвался.
5. **Тесты:** Написать тест, который отправляет на `/chat` огромный JSON (5 МБ) с кучей спецсимволов и кавычек. Ожидание: `200 OK`.
